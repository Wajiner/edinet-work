# 3Dマルチプル・スクリーニング（日本株 3D財務指標分析ツール）

3つの財務指標の組み合わせによる日本株企業の分布を、3Dバブルチャートで可視化するスクリーニングツールです。データは同梱していません。起動直後は空の状態で、右上「データ管理」→「JSONを読み込む」から、付属のPythonスクリプトで取得したJSONを読み込んで使います。

## サイトの起動方法

```bash
python -m http.server 8000
```

起動後、ブラウザで `http://localhost:8000` を開きます。

## 現在完成している機能

1. **3Dバブルチャート（Plotly.js使用）**
   - X軸・Y軸・Z軸それぞれに、次の25種類の基本指標を割り当て可能（分類ごとにグループ表示）。
     - 規模：売上高、営業利益、純利益、時価総額、総資産
     - 利益率：営業利益率、純利益率、営業キャッシュフロー率
     - 成長率：売上高成長率、営業利益成長率、純利益成長率
     - 株価評価：PER、PBR、PEGレシオ、EPS、BPS、基準株価、株価パフォーマンス
     - 資本効率：ROE、ROA
     - 財務健全性：自己資本比率、配当利回り、配当性向
     - キャッシュフロー：フリーキャッシュフロー、現金等
   - 球体の大きさ＝時価総額、色＝業種。
   - マウスドラッグで回転、スクロールで拡大縮小、ホバーで企業詳細を表示。
   - 業種凡例をクリックすると該当業種の表示・非表示を切り替え可能。
   - 球体を左クリックすると、その企業の主要財務情報がチャートの下に表示されます。決算期を列、指標を行にした一覧です。
     - 列は左から **会社予想／最新決算期／1期前／2期前…** の順です。各列の見出しには、相対位置に加えて決算期（例: `2025/06期`）と**決算発表日**を併記します。
     - 決算期の列はその期の実績値、「会社予想」列は最新決算期の発表時に開示された翌期の予想値です（青字）。
       - **売上高・営業利益・純利益・各成長率・EPS**：実績を全期ぶん並べ、予想は「会社予想」列にのみ載せます（過去の期の予想は結果が出ているため）。
       - **PER・PEGレシオ**：実績ベースと予想ベースで水準が変わり両方の推移に意味があるため、決算期の列を予想で埋めた行を別に設け「実績」「予想」バッジで区別します。この行は「会社予想」列と値が重複するため同列を使いません。
       - **上記以外**（時価総額・総資産・利益率・PBR・BPS・基準株価・ROE・ROA・自己資本比率・配当・キャッシュフロー）：決算短信に会社予想の開示欄が存在しないため実績のみです。
     - 表示の割り当ては `js/app.js` の `DETAIL_FORECAST_MODES` で定義しています。
     - 決算期ラベルと決算発表日は、J-Quantsから取得したJSONを読み込んだ場合にのみ表示されます（`financials.periodLabels` と、`financials.raw.DiscNo` を `rawStatements[].DiscDate` に突き合わせて解決）。これらを含まない古いJSONや既定の埋め込みデータでは、相対位置の表記だけになります。
     - 値を1つも持たない決算期の列と、その企業に値がない指標の行は省かれます。
   - 球体を右クリックするとその企業をチャートから非表示にできます。

2. **軸の設定（基本指標＋種別＋決算期）**

   軸には「基本指標」を選び、その直下に現れる補助セレクタで内訳を指定します。以前は「予想PER」「PER・1期前」のように全ての組み合わせを一覧に並べていましたが、選択肢が30項目を超えて探しにくかったため、この2段階方式に変更しました。

   - **種別**：実績と会社予想の両方がある指標（売上高・営業利益・純利益・成長率・PER・PEGレシオ・EPS）で選択できます。実績しかない指標では種別セレクタは表示されません。会社予想は開示資料に含まれる翌期の会社予想値（`NxFSales` 等）を使います。
   - **決算期**：最新決算期／1期前／2期前…を**軸ごとに独立して**指定できます。X軸に「売上高・最新決算期」、Y軸に「売上高・1期前」といった組み合わせも可能です。企業によって決算期末の月が異なるため、期間は暦年ではなく各社の相対位置（最新決算期から何期前か）で指定します。
   - **対数スケール**は指標を選んだ時点で自動的に切り替わります（PER・時価総額のように分布が広い指標はON、利益率・成長率のようにマイナスを取りうる指標はOFF）。チェックボックスで手動変更もできます。
   - フィルターの時価総額下限、注目企業パネル、分析レポートのサマリーは、軸の期間指定とは独立に常に最新決算期の実績値を使います。

   **PEGレシオ**は PER ÷ 純利益成長率(%) で算出します。実績（PER ÷ 実績成長率）と会社予想（予想PER ÷ 予想成長率）を選べます。成長率がマイナスの企業はマイナスのPEGレシオとしてそのまま表示し、成長率が0または欠損の場合のみ欠損（`-`）として扱います。

   **株価パフォーマンス**は、開始期の基準株価から終了期の基準株価までの騰落率(%)です。この指標だけは決算期を1つではなく「開始期」「終了期」の2つ指定します。基準株価（`financials.refPrice`）は各決算の発表日翌営業日の終値で、PER・PBR・時価総額の算出にも使っている値です。

   なお、PEGレシオ（実績）・株価パフォーマンス・EPS・BPS・基準株価は `refPrice` / `eps` / `bps` / YoY実績成長率のフィールドを参照します。これらの項目に対応する前のスクリプトで取得した古いJSONにはこれらが含まれないため、その場合は値が `-` になります。最新のスクリプトで取得し直してください。

3. **フィルター機能**
   - 市場区分・業種（複数選択）・時価総額の下限スライダー・企業名/証券コードのキーワード検索。
   - **指標でフィルター**：X・Y・Z軸に割り当てていない指標でも絞り込めます。指標を選んで「追加」すると、軸設定と同じ**種別（実績／会社予想）**と**決算期**のセレクタが現れ、その条件での値に対して最小・最大を指定します（株価パフォーマンスの場合は開始期・終了期）。複数追加でき、すべてのAND条件になります。

4. **注目企業パネル**：フィルター後の企業を時価総額順に上位12社表示。項目をクリックすると、球の左クリックと同じ主要財務情報がチャート下に表示されます。

5. **分析レポートモーダル**：対象企業数・合計時価総額・平均指標のサマリーと、時価総額上位30社の一覧テーブル。

6. **データ管理**：右上「データ管理」から、JSONファイルの保存／読み込み、初期の実データセットへのリセットが可能。

7. **使い方ガイド・免責事項モーダル**、**レスポンシブ対応**（PC / タブレット / スマートフォン）。

## データモデル・データソース

### 出力JSONに保存される内容

指標を1つ追加するたびに全銘柄を再ダウンロードするのを避けるため、スクリプトは決算APIから返ってきた情報をほぼそのまま保存します。企業1社ぶんの構造は次の通りです。

| キー | 内容 |
|---|---|
| `financials.<指標名>` | サイトが軸として直接使う、算出済みの指標（各期10スロットの配列） |
| `financials.raw.<APIのキー名>` | その期の開示に含まれる**数値フィールド全件**を、J-Quantsのキー名のまま配列化したもの（`NxFEPS`、`OdP`、`CFF` など） |
| `financials.refPrice` / `sharesOutstanding` | PER・PBR・時価総額の算出に使った基準株価（決算発表日の翌営業日終値）と発行済株数 |
| `rawStatements` | `/fins/summary` のレスポンス全件（**四半期開示を含む**）をそのまま保存したもの |

このため、新しい指標を軸に追加したくなった場合、**多くはデータを取り直さずに** `financials.raw.<キー名>` を参照するだけで済みます。株価そのものは日足10年分と巨大なので生のままは保存していませんが、実際に計算へ使った `refPrice` を残してあるため、株価ベースの新しい比率も再取得なしで算出できます。

**欠損について**：契約プランによって開示データの提供期間が異なります。提供期間の短いプランでは、多くの企業で直近決算期以外の値が欠損（`null`）になり、「1期前」「2期前」を選ぶと対象企業が大幅に減ることがあります。成長率指標は前期実績（YoY）だけでなく、同一開示内の会社予想値を使ったものも併せて算出しているため、この制約を受けにくくしています。

**予想PBRについて**：J-Quants APIには予想BPSに相当する項目が存在しない（決算短信の開示制度上、「予想の1株当たり純資産」という開示項目自体がない）ため、予想PBRは提供していません。予想PERは翌事業年度の予想EPS（`NxFEPS`）から算出しています。

**古いJSONを読み込んだ場合**：スクリプトに項目を追加する前に取得したJSONには、新しい指標のフィールドが含まれません。その場合、該当する軸の値は`null`として扱われます（エラーにはなりません）。最新のスクリプトで取得し直したJSONを読み込んでください。

### データの更新方法
ブラウザから直接J-Quants APIキーで接続する機能は、CORS制限により安定して動作しないため本サイトでは提供していません。データを更新するには、付属のPythonスクリプトを使用してください。

1. [Google Colab](https://colab.research.google.com/) を開き、「ファイル」→「ノートブックを新規作成」。
2. `jquants_v2_bulk_download.py` の内容をすべてコピーし、Colabの1つのコードセルに貼り付けます（`jquants_v2_bulk_download.ipynb` がある場合はそれを直接アップロードしてもOKです）。
3. セルの先頭付近にある設定値を必要に応じて編集します。市場区分は実行時に対話で選ぶため、通常は `PLAN` 以外そのままで構いません。
   - `PLAN`：ご契約プラン（`"free"` / `"light"` / `"standard"` / `"premium"`）
   - `TARGET_MODE`：`"universe"`（既定。上場銘柄一覧から市場区分で絞り込み）／`"curated"`（動作確認用の固定リスト）／`"custom"`（`CUSTOM_CODES` の銘柄のみ）
   - `PARALLEL_WORKERS`：並列で取得するワーカー数（既定8。`1`で従来どおりの逐次実行）
   - `SAVE_EVERY`：途中保存の間隔（既定200社ごと。`0`で無効）
   - `INCLUDE_RAW_STATEMENTS`：四半期を含む生の開示データを出力に含めるか（既定`True`。→「出力ファイルのサイズ」参照）
   - `BATCH_SIZE`：1回の実行で処理する銘柄数の上限（`None`なら全件）
   - `FETCH_DIVIDEND`：配当情報も別途取得するか（通常は不要）
4. セルを実行（▶ボタン、または Shift+Enter）します。実行中に、上場銘柄一覧の再取得要否とダウンロードする市場区分を対話で聞かれます。
   - 市場区分は `0`（またはEnter）で**プライム＋スタンダード＋グロースを1回の実行でまとめて取得**します。単独指定、`1,3` のようなカンマ区切りの複数指定も可能です。
5. 実行中にAPIキーの入力を求められます。J-Quantsのダッシュボードで発行したAPIキーを貼り付けてEnterを押してください（入力内容は画面に表示されません）。
6. しばらく待つと（Freeプランは特に時間がかかります）、進捗バーが表示されながらダウンロードが進みます。`SAVE_EVERY` 件ごとに途中保存されるため、Ctrl+Cや切断で中断しても、同じセルを再実行すれば続きから再開できます。
7. 出力ファイルが既にある場合、「上書きしますか？」と聞かれます。
   - **N（既定）**：まだ取得していない銘柄だけを追加します。途中で中断した続きを処理したい時はこちらです。
   - **y**：全銘柄を取り直します。**このスクリプトに取得項目を追加した後は、取得済みの銘柄にも新しい項目を入れるためyを選んでください。** 既存ファイルは `.bak` を付けた名前で退避されるので、新しいデータの取得が終わったら削除して構いません。
8. 完了すると **`jquants_dataset_universe.json`（市場区分によらず1ファイル）** が保存されます。各企業のデータには `fetchedAt` フィールド（取得日付。YYYY-MM-DD形式）が記録されているため、データの鮮度を把握・管理できます。
9. サイトの右上「データ管理」→「JSONを読み込む」から、そのJSONファイルを選択してアップロードしてください。1ファイルなので取り込みも1回で済みます。

#### 市場区分ごとの旧ファイルからの移行

以前のバージョンは `jquants_dataset_universe_prime.json` のように市場区分ごとにファイルを分けていました。これらが残っている状態で新しいスクリプトを実行すると、統合するか聞かれます。`y` を選ぶと取得済みのデータをそのまま `jquants_dataset_universe.json` へ引き継ぐため、**全件をダウンロードし直す必要はありません**（証券コードが重複する場合は先に読んだ方を残します）。統合元のファイルは削除せずに残るので、結果を確認してから削除してください。

#### 並列取得について

`PARALLEL_WORKERS` 件を並列で取得します。APIの1分あたりリクエスト上限は全ワーカーで共有するリミッター（`RateLimiter`）が守るため、ワーカー数を増やしても上限を超えることはありません。短縮されるのは「1リクエストごとの応答待ち時間」が重なる分なので、レート上限に余裕のある Standard 以上のプランほど効果が大きく、Free プラン（5回/分）ではほとんど変わりません。

#### 出力ファイルのサイズ

`INCLUDE_RAW_STATEMENTS = True`（既定）は、四半期を含む `/fins/summary` の生レスポンスを `rawStatements` として保存します。将来サイトで四半期データを扱うための備えですが、これが1社あたり約49KBとファイルサイズの過半を占めます。

| 設定 | 1社あたり | 全3市場（約5,900社） |
|---|---|---|
| `INCLUDE_RAW_STATEMENTS = True`（既定） | 約55KB | 約320MB |
| `INCLUDE_RAW_STATEMENTS = False` | 約7.5KB | 約45MB |

四半期データを使う予定がなければ `False` を推奨します（ブラウザへの取り込みも軽くなります）。切り替えた後は上書き取得（手順7で `y`）が必要です。なお出力JSONはインデントを付けずに書き出します（インデントだけで全体の約4割膨らむため）。

### 企業概要の表示（EDINET連携・任意）

球を左クリックしたときの財務パネルに、その会社の**事業の内容**を表示できます。出典は金融庁EDINETの有価証券報告書【事業の内容】で、法定開示情報のため二次利用が可能です。

**株探など外部サイトのスクレイピングは行いません。** 株探は自動アクセスに対してHTTP 403を返して明確に拒否しており（`robots.txt` も銘柄ページも403）、突破にはUser-Agent偽装などアクセス制御の回避が必要になります。加えて株探の企業概要文は同社の編集著作物です。パネルの「企業概要 株探へ ↗」は通常のリンクなので、こちらは問題なく利用できます。

#### 使い方

1. [EDINET API](https://api.edinet-fsa.go.jp/) の「EDINET API機能」から無料の利用登録を行い、Subscription-Key を取得します。
2. 環境変数に設定します。

   ```bash
   $env:EDINET_API_KEY = "取得したキー"
   ```

3. 静的配信用の `serve_nocache.py` の代わりに `edinet_server.py` を起動します（静的ファイルの配信機能も含んでいます）。

   ```bash
   python edinet_server.py 8010
   ```

4. 初回のみ、パネルに出る「索引を作成」ボタンを押します（数分）。以降は銘柄を選ぶだけで自動表示されます。

#### なぜローカルサーバー経由なのか

ブラウザから直接EDINET APIを呼ばない理由が3つあります。

- EDINET APIはCORSヘッダを返さないため、ページのJavaScriptからは呼び出せません。
- APIキーをブラウザに置かずサーバー側に留められます。
- 取得結果を `edinet_cache/` にキャッシュでき、同じ銘柄の再表示が即座になります。

また、全社ぶんを一括ダウンロードしてデータセットJSONに含める方式は採っていません。EDINETの書類取得APIは1社ごとに有報のXBRLパッケージ（数MB）を返すため、約5,900社では10〜20GB・数時間規模になる一方、実際に見るのは一度に数社だけだからです。

#### 「索引」について

EDINETの書類一覧APIは**提出日でしか検索できず、銘柄コードで引くことができません**。そのため初回だけ提出日を400日ぶん遡って走査し、`secCode → 有価証券報告書のdocID` の対応表を `edinet_cache/index.json` に作ります。400日なのは、有報の提出期限が決算期末から3か月以内で、決算期末が会社ごとに異なるため、全社の最新有報を拾うには1年分＋猶予期間が必要になるためです。索引は30日を過ぎると古い扱いになります。

`EDINET_API_KEY` を設定していない場合や、`serve_nocache.py` で開いた場合は、企業概要の欄は表示されないだけで他の機能はそのまま使えます。

## 注意事項

- APIキーはColabのセル内でのみ使用され、ファイルに書き出したり外部送信したりすることはありません（このスクリプト自身がAPIキーを保存する処理を含んでいません）。
- Freeプランは1分あたり5リクエストまでのため、多数の銘柄を全件ダウンロードすると数十分程度かかります。並列取得（`PARALLEL_WORKERS`）を上げてもこの上限は超えないため、Freeプランでは短縮効果がほとんどありません。
- `fins/summary` や `fins/dividend` のレスポンス項目名は、J-Quants公式のV1→V2移行ガイドで明示された株価カラムの短縮形以外は仕様が完全には確認できていないため、複数の候補フィールド名を試す防御的パース処理を実装しています。実際の項目名が想定と異なる場合、一部の値が取得できないことがあります（取得できた項目のみ反映され、それ以外は欠損値として扱われます）。
- 出力JSONの形式は、サイトの `js/dataset-store.js` の `importFromFile()` が読み込める形式（`{"companies": [...], "meta": {...}, "fiscalYears": [...]}`）に準拠しています。
